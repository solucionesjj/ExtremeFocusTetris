`AGENT.md`'s "Estado del repositorio" has full file-by-file detail. Things worth knowing before touching this code:
- Domain entities are hand-written immutable classes, not `freezed` (Phase 1).
- Starting a game (or anything that mutates provider state) from a widget's `initState` must be deferred (e.g. `Future.microtask`), or Riverpod throws (Phase 2).
- **`createAppRouter()` in `core/routing/app_router.dart` is a factory, not a top-level singleton** — `ExtremeFocusTetrisApp` (a `ConsumerStatefulWidget`) builds one instance in a `late final` field of its `State`. Making it a global singleton again would leak navigation location across widget tests run in the same process (this actually happened and broke 2 of the 4 navigation tests until fixed).
- Never call `ref.read(...)` inside a `State.dispose()` — Riverpod forbids reading a provider after its element is disposed, and during a full widget-tree teardown `dispose()` can run after that point. Capture whatever you need (e.g. a service instance) in `initState` instead. This was a real bug in `GameScreen.dispose()`, caught by the navigation widget tests.
- The bundled `.ogg` audio assets are synthesized placeholder tones for wiring purposes, not final sound design.
- A `GameScreen`'s `Ticker` runs indefinitely — widget tests touching it must use bounded `tester.pump(duration)` instead of `pumpAndSettle()`, and unmount the tree at the end (`tester.pumpWidget(const SizedBox.shrink())`) so `dispose()` stops the ticker before the test ends.
- **`hive_generator` is deliberately not a dependency** — its latest release needs `source_gen ^1.0.0`, which conflicts with `riverpod_generator`'s `source_gen ^2.0.0` (adding it makes `flutter pub add` fail version solving). The three Hive `TypeAdapter`s are hand-written in the exact shape codegen would produce instead — don't try to add `hive_generator` again without resolving that conflict first.
- `ThemeModeController`/`LocaleController` no longer exist as separate providers — theme and locale live inside `SettingsState`/`SettingsController` alongside every other preference, in one `settings_box` record.
- **Any test touching `settingsControllerProvider`, `statisticsControllerProvider`, `gameRepositoryProvider`, or a repository implementation directly needs Hive boxes open first** — call `setUpHiveForTesting()` from `test/test_helpers/hive_test_setup.dart` at the top of the test file's `main()`. `main()` (the real app entry point) opens these boxes before `runApp`; tests bypass `main()` entirely.
- `GameController._playSfx(event)` is the only method that should play in-game SFX — it applies Focus Mode's -6dB attenuation. Calling `ref.read(audioServiceProvider).playSfx(...)` directly from `GameController` skips that attenuation.
- **`GameScreen`'s `_lineClearEffectController` must start at `value: 1`**, not the `AnimationController` default of 0 — its idle `flashOpacity` is computed as `1 - value`, so a default-0 start would render the line-clear flash at full opacity before any line has ever cleared. If you add another controller driving an idle-should-be-zero effect the same way, remember this gotcha.
- Particle emission needs pixel coordinates, which only `BoardPainter.paint()` used to compute — that math now lives in `board_geometry.dart`'s `BoardGeometry.of(Size)` so `GameScreen` can reuse it (via a `LayoutBuilder`-captured `Size`) without duplicating the cellSize/offset formula.
- The vertical "collapse" of rows above a cleared line (spec.md section 7's animation phase 2, 120–320ms) is deliberately **not animated** — the board updates discretely/instantly like the rest of piece movement, consistent with spec.md's own "debe sentirse precisa" rationale. Don't treat this as an oversight if you're auditing spec compliance.
- **High contrast is orthogonal to `ThemeMode`, not a fourth value of it** — Flutter's `MaterialApp.themeMode` only knows light/dark/system, so `app.dart` picks between `AppThemeLight`/`AppThemeHighContrastLight` (and the dark equivalents) based on `settings.highContrast`, then still hands the result to `theme`/`darkTheme` as usual. Don't try to add a `ThemeMode.highContrast` enum value — it doesn't exist.
- **`SwitchListTile`/`Slider` interaction in widget tests needs `tester.runAsync()`, or it can deadlock** — tapping any Settings toggle triggers `SettingsController._persist()`, a fire-and-forget Hive `box.put()` (real disk I/O). Do the tap under the test's normal `FakeAsync` zone and let the test end, and `setUpHiveForTesting()`'s `tearDown()` can hang for real inside `box.clear()` waiting on that write (confirmed by bisecting with print markers: `tearDown` prints `start clear` and then never returns; this isn't new to Phase 8, no earlier test had ever tapped a Settings switch). Fixed in Phase 9: wrap the tap + `pump()` + a short real delay in **one** `tester.runAsync(() async {...})` call — see `_tapAndLetHiveWriteSettle` in `test/widget/settings_screen_test.dart` (also documented on `setUpHiveForTesting` itself). A trailing real delay *outside* `runAsync` is not enough; the tap and pump must be inside it too.
- **Don't put a wide widget (`SegmentedButton`, a long `DropdownButton`) in a `ListTile.trailing`** — it squeezes `title` down to almost nothing, and Flutter wraps a too-narrow single word one character per line (this happened for real to the Theme row: "Tema"/"Theme" rendered vertically, letter by letter). Put it in `subtitle` instead, like the volume sliders already do.
- **The Android SDK's `emulator` on `PATH` may resolve to the legacy shim** (`$ANDROID_HOME/tools/emulator`), which computes library paths relative to the shell's cwd instead of its own location and fails with a `qemu-system-aarch64: No such file or directory` error when launched from outside the SDK folder. Use the modern binary directly: `$ANDROID_HOME/emulator/emulator -avd <name>`.
- **Give each `integration_test/*.dart` file exactly one `testWidgets`** — a single file with two scenarios produced real cross-test contamination on this harness (an `AudioPlayer` from the first test showed up already "disposed" inside the second, despite `testWidgets` supposedly starting each test with a fresh widget tree). Splitting into `full_flow_test.dart`/`resume_test.dart` (one scenario each) made each its own on-device app launch and the problem disappeared entirely.
- **Don't simulate an app/process restart in a widget or integration test via `pumpWidget(const SizedBox.shrink())` then re-pumping** if the app has started any `audioplayers` `AudioPlayer` (e.g. by starting the ambient loop) — its internal frame-position-tracking ticker isn't tied to the widget tree and keeps scheduling callbacks after the tree is gone, tripping "An animation is still running even after the widget tree was disposed." Either avoid that pattern for audio-touching tests, or explicitly `await audioService.dispose()` right before the teardown pump (mind the order: this disposes the `AudioPlayer`s, so anything that calls `AudioService.startAmbient()` — e.g. `GameController.resumeSession()` — must run *before* it, not after).
- **`const` widget instances canonicalize** — two `const Foo(...)` expressions with identical arguments are the exact same object at runtime. Re-pumping `const ProviderScope(child: ExtremeFocusTetrisApp())` a second time to force a rebuild does nothing (`Element.update` sees `identical(old, new)` and skips it); dropping `const` for that specific call is required if the goal is forcing a fresh build pass. This alone still isn't enough to force `HomeScreen` to re-read `GameRepository.hasSavedSession()`, though — see the `resume_test.dart` comment for why that check is done against the repository directly instead of the "Continuar" button label.

## What this project is

**Extreme Focus Tetris**: a personal-use Android app (Flutter/Dart) that reframes Tetris as a deep-focus concentration tool. No ads, no IAP, no accounts, no network access, no telemetry, no background music — see `spec.md` sections 1–2 for the full product philosophy.

## Non-negotiable constraints

- **Zero network**, even on first launch (e.g. fonts must be bundled as local assets, not fetched via `google_fonts`'s runtime mode).
- **Zero telemetry/ads/IAP/accounts** — no cloud analytics or crash-reporting SDKs.
- **No background music**, ever — only the ambient "tic-toc" loop + SFX.
- **No third-party physics engine** — movement is grid-based and deterministic; particle effects use a simple manual simulation.
- **60 FPS stable** and **playable within 5 seconds of launch** are acceptance requirements, not aspirations.
- Don't add out-of-scope features (multiplayer, backend, push notifications) without updating `spec.md` first.

## Architecture (summary)

Clean Architecture + Feature-First + MVVM, with **Riverpod** for state management and as the DI container (see `spec.md` 3.1 for the justification vs. Provider/Bloc). Dependency rule: `presentation → domain ← data`; `domain` is pure Dart (no `package:flutter`, no Hive).

- `lib/core/` — theme, constants, routing (`go_router`), cross-cutting services (`AudioService`, `HapticService`, `GameTickerService`), root DI.
- `lib/features/<feature>/domain|data|presentation/` — one folder per feature: `game`, `settings`, `statistics`, `home`, `splash`, `game_over`, `about`.
- `lib/shared/widgets/` — widgets reused across features.

Full folder tree: `spec.md` section 3.4. Key technical decisions to respect when implementing (persistence via Hive with domain entities kept framework-agnostic, board rendered via a single `CustomPainter`/`RepaintBoundary` rather than a widget per cell, game loop driven by a decoupled `Ticker`, fixed-size `ParticlePool`, SRS rotation with the exact wall-kick tables, 7-bag piece generator, exact scoring/level tables): see the decision table in `AGENT.md` and `spec.md` section 8 (gameplay), 13 (persistence), 15–16 (performance/memory), 24 (dependencies).
